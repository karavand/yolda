# فرانت‌اند وب سوپراپلیکیشن یولدا — نسخه ۳.۱.۲

این بسته نسخه وب تعاملی، واکنش‌گرا و قابل‌نصب (PWA) یولداست. پروژه با HTML، CSS و JavaScript خالص ساخته شده، وابستگی خارجی و مرحله Build ندارد و مستقیماً روی هاست استاتیک اجرا می‌شود.

## اجرای محلی

در پوشه پروژه یک وب‌سرور محلی اجرا کنید:

```bash
python -m http.server 8080
```

سپس `http://localhost:8080` را باز کنید. اجرای مستقیم `index.html` نیز ممکن است، اما Service Worker فقط روی HTTP/HTTPS فعال می‌شود.

## پیشنهاددهنده هوشمند یولدا

فایل `assets/js/recommender.js` یک موتور پیشنهاددهنده محلی و توضیح‌پذیر است که بدون API خارجی کار می‌کند. ورودی طبیعی فارسی و پرسش‌نامه را با داده‌های واقعی کاتالوگ ترکیب می‌کند و این سیگنال‌ها را در رتبه‌بندی دخالت می‌دهد:

- بودجه و زمان تحویل
- سبک و حال‌وهوای غذایی
- رژیم غذایی، کالری و میزان تندی
- امتیاز، محبوبیت و موجودی
- شباهت متنی و معنایی ویژگی‌ها
- بازخورد مثبت یا منفی کاربر
- تنوع نتایج برای جلوگیری از پیشنهادهای تکراری

جریان AI در سه مرحله «درخواست، تنظیم دقیق، پیشنهادها» طراحی شده است. کاربر از ابتدا میان غذا، سوپرمارکت و داروخانه انتخاب می‌کند و نمونه‌درخواست‌های هر سرویس، تحلیل مرحله‌ای و اصلاح سریع «اقتصادی‌تر، سریع‌تر، سالم‌تر یا محبوب‌تر» ادامه مسیر را کوتاه می‌کنند. محدودیت‌های فعال روی نتیجه نمایش داده می‌شوند، بهترین تطابق برجسته است و انتخاب‌های پرسش‌نامه مستقیماً وارد رتبه‌بندی می‌شوند. برای هر پیشنهاد، درصد تطابق و دلیل انتخاب نمایش داده می‌شود. تاریخچه، سرویس انتخابی و بازخورد روی همان دستگاه ذخیره می‌شوند.

## فونت و هویت بصری

فونت اصلی در `assets/css/tokens.css` با نام `Dana` تعریف شده است. شش فایل مجاز تحویلی با وزن‌های ۴۰۰، ۵۰۰، ۶۰۰، ۷۰۰، ۸۰۰ و ۹۰۰ در `assets/fonts` قرار دارند، دو وزن اصلی Preload می‌شوند و همه وزن‌ها در کش آفلاین Service Worker ثبت شده‌اند.

لوگوی تحویلی یولدا در `assets/brand/yolda-logo.png` فعال است. رنگ رسمی بنفش `#5E1A84` و زرد `#FFC400` است. همه رنگ‌ها، شعاع‌ها، سایه‌ها و تایپوگرافی در `tokens.css` متمرکز شده‌اند. نام دقیق فایل‌های برند، فونت و دو لودینگ و روش فعال‌سازی آن‌ها در `BRAND_AND_LOADING_ASSETS.md` مستند شده است.

## اتصال به بک‌اند

این تحویل، فرانت‌اند کامل است؛ OTP، پرداخت بانکی، نقشه، Push، آپلود واقعی فایل و داده‌های عملیاتی فعلاً با داده نمایشی اجرا می‌شوند. نقطه‌های اتصال UI در `assets/js/app.js` متمرکزند و می‌توان آن‌ها را به API واقعی جایگزین کرد.

برای اتصال، در `assets/js/config.js` مقدار `mode` را روی `live` و `apiBaseUrl` را روی آدرس HTTPS بک‌اند قرار دهید. قراردادهای احراز هویت، سفارش و پشتیبانی در `assets/js/api.js` آماده شده‌اند. Access Token فقط در Session Storage نگه‌داری می‌شود و Refresh Token برای پیاده‌سازی سروری باید به‌صورت HttpOnly Cookie صادر شود.

## تست سلامت

برای بررسی ۱۰۰ مسیر، لینک‌های داخلی، شناسه‌های تکراری، ساختار و نام دسترس‌پذیر فرم‌ها، متن جایگزین تصاویر، اکشن دکمه‌ها، ۱۶۷ آیکون و پیشنهاددهنده اجرا کنید:

```bash
node tests/smoke.cjs
```

نتیجه دو دور ممیزی رابط، بازطراحی خانه، ریسپانسیو و تعاملات در `QA_REPORT.md` ثبت شده است.

سه تست مرورگری تکمیلی نیز وجود دارد: `tests/ui-audit.cjs` هر ۱۰۰ مسیر را در عرض‌های مرجع، پوسته تیره و حالت `--accessibility` برای متن بزرگ، کنتراست زیاد و حرکت کم بررسی می‌کند؛ `tests/flows.cjs` همه ۲۸ نوع فرم، انتشار و ماندگاری CMS، پوسته و هماهنگی زنده با سیستم را اجرا می‌کند و `tests/pwa.cjs` فعال‌سازی Service Worker و اجرای آفلاین را می‌سنجد. این تست‌ها به Playwright و یک وب‌سرور محلی نیاز دارند؛ تست `smoke.cjs` بدون وابستگی خارجی اجرا می‌شود.
